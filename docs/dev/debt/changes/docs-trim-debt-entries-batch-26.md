# relinker

## change In executables and guest modules with a `PT_SCE_DYNLIBDATA` segment

- In `PT_SCE_DYNLIBDATA` executables and guest modules, Windows/macOS [code analysis](../../../core/relinker/relinker/src/analysis/CodeInstructionCollector.cpp) spans from the end of `PT_INTERP` (or `/libexec/ld-elf.so.1` when uncovered, as in OpenOrbis modules) to the end of the PLT after the last unwind function, or that function's end if the PLT precedes code (as in CUSA02636's `libSceFios2.prx` and `libc.prx`, PLT at 0xc8); executable scans use the same end. Guest modules with PLT relocations lacking a PLT before/after unwind functions, or overlapping one, fail like executables. Code past that end (e.g. an unwindless `DT_FINI` after the last unwind function, called on exit in Windows/macOS) is unanalyzed: TLS accesses aren't rewritten; ELF entry, `DT_INIT`, `DT_FINI`, branches and pointers into it are ignored; function symbols or init/fini array entries into it fail conversion.

## change `--to-rosetta` lowers what Rosetta lacks on top of `--to-intel`

- `--to-rosetta` lowers atop `--to-intel` ([matcher](../../../core/relinker/codegen/src/x86/Amd64OnlyInstructionMatcher.cpp)): ANDN, BLSI, BLSMSK, BLSR, SHLX, SHRX, SARX, RORX, BZHI, BEXTR, MULX; RDSEED->RDRAND; CLWB->NOP; RDPID->0; RDTSCP unchanged + ECX=0 (TSC_AUX=0xAAAAAAAB, also M5 macOS 27.0.1; unmovable sites kept). RDRAND/other BMI depend on host; ADCX/ADOX fault unconverted (no ADX in CPUID). Unreported in CPUID (leaf 7=0, 1/0x80000001 omit): AVX2, FMA, BMI1/2, F16C, MOVBE run on M5 Max; on M1, ANDN/RDRAND fault on macOS 15.3.1 and run on 26.6.2 with BMI1/2, TZCNT, LZCNT, POPCNT, MOVBE, FMA, AVX2, F16C (RDSEED/RDPID/CLWB/ADCX/ADOX SIGILL); on M5 macOS 26.4, BMI1/2, LZCNT, PREFETCHW, CLFLUSHOPT, AVX/2, FMA, F16C, MOVBE run (PDEP/PEXT/BEXTR/BZHI/LZCNT/TZCNT match Intel SDM on 200,000 random inputs each), while RDSEED/CLWB/RDPID/ADCX/ADOX/SHA/AVX-512F fault. Converter tests cover them (ANDN on M1 Rosetta; others on M5 Max, outside CI).

## change 1/sqrt(x) computed as SQRT then DIV

- `--to-intel` replaces approximate legacy SSE/VEX.128 register (V)RSQRTPS, (V)RCPPS, (V)RSQRTSS and (V)RCPSS with [1/sqrt(x) computed as SQRT then DIV](../../../core/relinker/codegen/src/x86/ReciprocalLowering.cpp) (rounds twice, up to 1 ULP off) and correctly rounded 1/x instead of AMD's undocumented tables. Intel's 1/sqrt(1.0)=0x3F7FF000 gives 0.99999994 after two Newton-Raphson steps, turning a renormalised identity quaternion into a NaN axis in PPSA21564; refined results are now exact, while unrefined ones can differ in low bits. Each site uses an out-of-line stub (2 jumps, spill below red zone, SQRTPS/DIVPS) that sets MXCSR flags and raises unmasked #XM; legacy SSE preserves upper YMM bits, VEX clears them. 256-bit/memory forms and <5-byte sites without a movable trailing instruction keep native ops (5 sites in PPSA21564 before RIP-relative moves were supported; not recounted).

## change XSAVEC raises an illegal instruction under Rosetta

- XSAVEC faults under Rosetta (compacted format) and stays unconverted; XSAVEOPT (`0F AE /6`) is rewritten in place to XSAVE (`/4`, keeping prefixes/operand) by [matcher](../../../core/relinker/codegen/src/x86/Amd64OnlyInstructionMatcher.cpp) under `--to-rosetta`. They differ only in init/modified optimizations ([Intel SDM volume 1](https://cdrdv2-public.intel.com/812382/253665-sdm-vol-1.pdf) ch. 13), so XRSTOR restores identically. On M5 macOS 27.0.1, XSAVE/XRSTOR handle x87, SSE and AVX in standard format though CPUID leaf 1 omits XSAVE/OSXSAVE and leaf 0xD sub-leaf 1 omits XSAVEOPT/XSAVEC. On M5 macOS 26.4 (where converter x86-64 tests execute replacement XSAVE under Rosetta), XSAVE writes XSTATE_BV=0x7 and XGETBV returns the same mask despite leaf 1 omitting XSAVE/OSXSAVE; XRSTOR was untested there.

## change [Nested image tables]

- [Nested image tables](../../../core/shader/recompiler/Optimization/src/ResourceTracker.cpp) support a V# loaded via a pointer from one scalar-buffer record origin (low-pointer Phi may merge constants; GPU faults on uncaptured 64-bit pointers) followed by an independently indexed T# or S#. Other origins, shared V# consumers, non-handle T#/S# word reads and deeper nesting stay refused. Snapshots scan <=524288 parent records (columns reading the same records with different V# offsets behind the pointer count once), hold 1048576 inner key slots across nested columns (equal V#s share a child snapshot per column), and cap the final map at 32 MiB. Nested T#s materialize from raw words without registered `resourceViews`, so 1D arrays past `maxImageArrayLayers` keep raw descriptors. Synthetic readback covers #6191; full title behavior is unverified.

## change [MIMG PCK2/PCK4 loads]

- [MIMG PCK2/PCK4 loads](../../../core/shader/recompiler/SpirvBackend/src/SpirvImageEmitter.cpp) (`image_load[_mip]_pck2/pck4`, 0x70/0x71/0x73/0x74) were measured on gfx1035 ([hardware oracle](../HW_ORACLE.md)) for identity-swizzled 2D images. ## change [D16 accesses of converted images]
