## change [V# bases off a DWORD boundary]

- [V# bases off a DWORD boundary](../../../core/shader/recompiler/SpirvBackend/src/SpirvMemory/SpirvMemoryInstructions.cpp) (shader recompiler) - raw accesses read exact bytes as on gfx1035 (Linux, UNALIGNED mode), differing from PS5 mode DWORD: on PS5 (13.40, measured 2026-10-19 via retail gfx1013 kernel), raw `buffer_load_dword` with V# base +1 byte or aligned base + `voffset=1` returned the aligned dword (0x44332211, not 0x55443322). `s_buffer_load` reads `(base & ~3) + (offset & ~3)` as on console. Unaligned formatted accesses throw. Atomics use byte address `base + offset` (incl. base low 2 bits): on gfx1031 (Win 32.0.21045.5002, HIP) with `buffer_atomic_add/_swap/_cmpswap` (bases +0..3, offsets 0..7), aligned addresses update the DWORD while unaligned ones halt dispatch (reported as unaligned access fault). Closes when: raw buffer accesses drop the low 2 address bits like console.
