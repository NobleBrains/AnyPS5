# libSceAgcDriver

## change [Sparse dma-buf imports]

- [Sparse dma-buf imports](../../../core/libs/prx/libSceAgcDriver/Graphics/src/GuestBufferMemory.cpp) (libSceAgcDriver): on Linux, shared-backed ranges >64 MiB import as one sparse buffer bound to 64 MiB udmabuf chunks on a dedicated sparse queue family if available (decided pre-import; later failure throws); non-64 KiB-aligned offsets start at the 64 KiB block below (`HostImport::lead`). Falls back to single udmabuf (kernel `size_limit_mb`=64 MiB default, else copied) if sparse block >64 KiB (RADV=64 KiB), a chunk memory type isn't accepted, backing file ends mid-last-chunk, or map-time import lacks a 2nd family (needs GPU mutex); NVIDIA proprietary imports no dma-buf. Run lists >64 MiB use sparse; <=64 MiB or unaligned runs use one udmabuf. Single runs <=32 MiB crossing a chunk use a 64 MiB udmabuf at +32 MiB; multi-run or >32 MiB cross-chunk ranges always use sparse. Declined sparse ranges become own BOs (amdgpu validates per submit).

## change [TRUNC_COORD]

- [TRUNC_COORD](../../../core/libs/prx/libSceAgcDriver/Graphics/src/GuestSamplerResource.cpp) (libSceAgcDriver) is not applied (normalized or unnormalized): point texel and bilinear weights follow host sampler rounding. On RDNA 2 (RX 6700 XT), S# `TRUNC_COORD` 0 rounds scaled coords to 8 fractional bits (ties to even) and 1 truncates for point and bilinear. AMD Windows driver 32.0.21045.5002 truncates nearest and rounds linear: `TRUNC_COORD` 0 point samples <=1/512 texel below an edge read below instead of above (`k / width` in f32 hits this for ~half of k), and `TRUNC_COORD` 1 bilinear weights can be 1/256 above console's. On gfx1036 (driver 31.0.22044.1), `TRUNC_COORD` 0 nearest 1/512 below an edge reads above and 1 reads below—it rounds where 32.0.21045.5002 on gfx1031 truncates, so tuning to that driver fails here; other drivers unmeasured.

## change [PA_SU_SC_MODE_CNTL.PROVOKING_VTX_LAST]

- [PA_SU_SC_MODE_CNTL.PROVOKING_VTX_LAST](../../../core/libs/prx/libSceAgcDriver/Graphics/src/Pipeline.cpp) (libSceAgcDriver) is unmeasured on console: bit 19 selects Vulkan last-vertex mode per opengnm `flatshade_first`. Rect-list flat inputs use vtx 0 (2 in last); GS gets strip/fan triangles in RX 6700 XT order, taking flat/layer from last index while keeping vtx order; non-pass-through flat via `v_interp_mov_f32` P10 (P20) use provoking vtx (#1413; first (last) throws). Barycentric tessellation gives corners last vtx flat values. Without `VK_EXT_provoking_vertex`, last mode uses first unless PS reads provoking vtx (flat, P10 flat, per-vtx/custom per-vtx, or non-PS-generated SPIR-V `Flat`/`PerVertexKHR`) or another stage decorates `Layer`/`ViewportIndex` non-`PerPrimitiveEXT`. With it, tessellation, explicit per-vtx flat inputs, and strips with PS vtx-slot reads (`v_interp_mov_f32` or 16-bit interp) throw (odd order varies by GPU).

## change [DB_SHADER_CONTROL.STENCIL_TEST_VAL_EXPORT_ENABLE]

- [DB_SHADER_CONTROL.STENCIL_TEST_VAL_EXPORT_ENABLE](../../../core/libs/prx/libSceAgcDriver/Graphics/src/State.cpp) (libSceAgcDriver) maps to `FragStencilRefEXT` from 2nd MRTZ channel of 32_GR/32_ABGR per Mesa ([`emit_ps_mrtz_export`](https://gitlab.freedesktop.org/mesa/mesa/-/blob/3e32b0e1f132231b7a972c1b0b5b06c7e16cf8b9/src/amd/common/nir/ac_nir_lower_ps_late.c#L194)); console unmeasured. It serves as both faces' test ref and `REPLACE_TEST` value, so ONES/REPLACE_OP, stencil clear draws, and UINT16_ABGR throw. Without the extension, bounded replay is used; draws drop the export when `StencilReferenceUnused` holds (no stencil test/attachment, or compare ignores ref and no reachable `REPLACE` via non-zero write mask), compiling PS at first draw instead of ABI resolution. Devices with the extension keep one PS variant.

## change [Compressed FMASK reads]

- [Compressed FMASK reads](../../../core/libs/prx/libSceAgcDriver/Graphics/src/MultisampleTarget.cpp) without an exact resident native owner throw. Native reads require 2 or 8 fragments (1/sample), 1 slice and mip, pipe-aligned DCC/CMASK, Z_64KB_X FMASK, and unchanged disjoint planes watched or compared by Linux write-watch probe (once per collect epoch); Windows deferred reads settle first (`WatchedAfterSettle`). Host stores independent samples with expanded FMASK values `0x76543210` (8x) and `0x02` (2x) per AMD PAL `c5e80007` `Gfx9Fmask::GetPackedExpandedValue` (shader turns 2x into `0x10`, 4 bits/sample per Mesa `mesa-25.0.0` `nir_lower_ms_txf_to_fragment_fetch`). Console equivalence is unmeasured; other layouts, standalone decoding, guest publication, and recipe reuse are unsupported. Metadata writes invalidate the view (except same-value CPU stores to compared planes).

## change [Multisampled color fills]

- [Multisampled color fills](../../../core/libs/prx/libSceAgcDriver/Graphics/src/MultisampleTarget.cpp) (libSceAgcDriver) - samples live on host, so uniform fills over the entire color memory (1 mip/slice of addrlib `ComputeThinBlockDimension`) clear the host image at next use; pending CMASK fast clears take precedence even over throwing fills. Partial fills, fills touching linear targets without computed footprints, and inexact clear values (sRGB channels not 0 or 1) throw at next use. Pre-first-use fills (host starts at 0), copies, and shader writes into color memory are unseen. Whole-memory uniform compute fills with exact clear values are not written to guest memory. Targets retire only on full unmap or allocation removal, so memory reuse while mapped leaves pre-fill bytes visible to unguarded V#/pointer buffer reads.
