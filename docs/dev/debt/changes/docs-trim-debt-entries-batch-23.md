# libc

## change [strtod, strtof, strtold](../../../core/libs/prx/libc/src/Strings.cpp)

- [strtod, strtof, strtold](../../../core/libs/prx/libc/src/Strings.cpp) (libc) - `strtod`/`wcstod`/`atof` parse `NAN(...)` via FreeBSD 11 gdtoa [`hexnan`](https://github.com/freebsd/freebsd-src/blob/release/11.0.0/contrib/gdtoa/hexnan.c) & [`strtod`](https://github.com/freebsd/freebsd-src/blob/release/11.0.0/contrib/gdtoa/strtod.c#L316-L328): optional `0x` hex, blanks start 32-bit word, 16 digits->52-bit payload under quiet+sign (0->1), other chars give default NaN to `)`, unterminated keeps payload/consumes `nan`. `strtold`/`wcstold` return qNaN (exp `0x7fff`, sig `0xc000000000000000`), consuming letters/digits/`_` to `)`. Matches PS5 (12.70) `libSceLibcInternal.sprx` payload (64 `strtod`, 50 `strtold`/`wcstod`, 18 `wcstold`, `nan(1 2)`, `nan( `+NUL+`)`) & title `libc.prx` `strtod`. Blank after digit with free word lacks NUL check (`nan(1 `+NUL+`)` reads past NUL on PS5, throws here); blank after `nan(` stops at NUL.

## change [_LLog](../../../core/libs/prx/libc/src/DinkumwareInternals.cpp)

- [_LLog](../../../core/libs/prx/libc/src/DinkumwareInternals.cpp) (libc) runs at the caller's x87 precision, so a guest thread starting at 53 bits (see `asinl`) gets the binary's 53-bit result, not the console's 64-bit one. It follows PPSA21564's `libc.prx` `_LLog` (0x3fd50): Dinkumware's `_LDunscale` split, 8-term `_LPoly` table, and split `ln 2`/`log10 e`/`log2 e` constants from the binary; `_Feraise` raises `FE_DIVBYZERO`/`ERANGE` on zero mantissa (including pseudo-zeros) and `FE_INVALID`/`EDOM` below zero. 4M random arguments under bases 0, 1, -1, 7, -9 match that code natively on Linux at 64-, 53- and 24-bit precision (host `logl`/`log10l`/`log2l` differed on 869,197, 2,000,696, 306,649 at 64 bits). That binary's `logl`, `log10l`, `log2l` call `_LLog` with 0, 1, -1, and this libc forwards them there too. Other SDK versions are uncompared.

## change [localtime, mktime](../../../core/libs/prx/libc/src/Time.cpp)

- [localtime, mktime](../../../core/libs/prx/libc/src/Time.cpp) (libc) on Windows use CRT `localtime_s`/`mktime` (~1970 to Jan 3001 UTC, CRT DST rule); out-of-range times shift by 400-year Gregorian cycles, getting that year's CRT rule instead of historical zone rules. On macOS `mktime` refuses <1900, so pre-1900 local time iterates subtracting `localtime_r`'s historical offset (local mean time before first transition) until stable, ignoring `tm_isdst` (so set `tm_isdst` with no zone DST stays standard time, whereas FreeBSD [`time1`](https://github.com/freebsd/freebsd-src/blob/stable/11/contrib/tzcode/stdtime/localtime.c#L2036) shifts by a daylight-standard offset difference). `gmtime` converts any year fitting `int` on both hosts.

## change [ios_base standard streams](../../../core/libs/prx/libc/src/LocaleSupport.cpp)

- [ios_base standard streams](../../../core/libs/prx/libc/src/LocaleSupport.cpp) (libc) `_Addstd` uses Dinkumware [ios.cpp](https://github.com/ganboing/crt.vc12/blob/master/src/ios.cpp) (`stdstr`, `stdopens`, `_Addstd`, `_Ios_base_dtor`): takes first free/matching slot 1..7 or shared slot 8 (`NSTDSTR`), stores 1-based index in `IosBase::standardStream` (`_Stdstr`; 0=non-std), and refcounts per slot (re-registering increments). Matches PS5 (13.60) homebrew payload calling `libSceLibcInternal`: with slots 1..7 held, 12 distinct + 1 repeated stream all got 8 (64-bit write at offset 0x8); slots 1..7 follow VC12. Counts are `int` (not `char`), both `_Addstd` and destructor lock the table, and out-of-range slot throws in dtor. Dtor decrements count, skips rest while >0, keeps slot pointer reserved, and titles destroy via `__cxa_atexit`; on last ref, unsupported stream storage/callback cleanup still throws and locale releases normally.

## change [Protecting a host thread's stack](../../../core/libs/prx/libkernel/DirectMemory/DirectMemory.cpp)

- [Protecting a host thread's stack](../../../core/libs/prx/libkernel/DirectMemory/DirectMemory.cpp) (libkernel) - on Windows `sceKernelIsStack` reports the whole stack reservation (committed top-down behind a guard page). Protecting over it changes only pages above the guard so stack growth/overflow still work; a protect from reservation bottom stopping short of the guard (like HotSpot stack guard zones) commits and protects them, though Windows advances the guard page down (3 pages on GitHub runners) and resets non-RW (including `PROT_NONE`) pages to RW once the stack nears (unlike console, which protects all reported pages; keeping it requires removing the guard page and updating TEB stack limit). On Linux main thread, unmapped pages from protect bottom up to stack top are mapped RW in place before protecting to avoid Linux's 1 MiB stack guard gap refusal; pages below remain unmapped/unreachable (unlike console).
