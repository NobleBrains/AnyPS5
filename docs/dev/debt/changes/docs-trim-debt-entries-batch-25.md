## change [pthread_setaffinity_np]

- [pthread_setaffinity_np](../../../core/libs/prx/libkernel/Pthread/Posix/Thread.cpp) (libkernel) - 17-23B sets return `ERANGE` (PS5 11.60 payload: 17, 20, 23B); bits past byte 8 return `EINVAL` per [`kern_cpuset_setaffinity`](https://github.com/freebsd/freebsd-src/blob/d106002967eff712894ab8b5337bbbff106ce5e0/sys/kern/kern_cpuset.c#L1235-L1246) (unmeasured). 8-16B sets succeed and <8 or >=24B return `ERANGE`, per rooklz on PS5 ([setter](https://github.com/boykopovar/AnyPS5/pull/7135#issuecomment-6390891591), [`cpuset_setaffinity`](https://github.com/boykopovar/AnyPS5/pull/9156#issuecomment-6391607043)), called by [FreeBSD libthr](https://github.com/freebsd/freebsd-src/blob/8c639945a44588f6cfdddfb057bb5aad88735da0/lib/libthr/thread/thr_affinity.c#L41-L62). Bits outside `sceKernelGetAvailableCpumask` are dropped; affinity is stored on the guest thread only.

## change [Host CPU check]

- [Host CPU check](../../../core/libs/prx/libkernel/System/src/HostCpu.cpp) (libkernel) - on Linux/Windows x86-64 hosts, libkernel load logs PS5 CPUID user-mode extensions and throws (naming host CPU) if any LLVM Zen 2 plain C/C++ extension (`-march=znver2`, [feature list](https://github.com/llvm/llvm-project/blob/llvmorg-19.1.7/llvm/lib/Target/X86/X86.td#L1459-L1513)) is missing: SSE-SSE4.2, SSSE3, POPCNT, LZCNT, BMI1, BMI2, MOVBE, CMPXCHG16B, LAHF/SAHF, AVX, AVX2, FMA, F16C, and OS AVX XCR0 state (#3719). `--to-intel`-converted SSE4A, CLZERO, SHA and intrinsic/prefetch-only AES, PCLMULQDQ, RDRAND, RDSEED, ADX, CLFLUSHOPT, CLWB, RDPID, XSAVEOPT, XSAVEC, PREFETCHW are logged but optional (missing ones fault with illegal instruction if run). macOS is unchecked as Rosetta support varies and CPUID omits some extensions; ANDN and RDRAND fault on M1 macOS 15.3.1 (see [Rosetta conversion limits](relinker.md)).

## change [getrlimit]

- [getrlimit](../../../core/libs/prx/libkernel/System/src/Process.cpp) (libkernel) - `RLIMIT_CPU`/`FSIZE`/`CORE`/`SBSIZE`/`VMEM`/`AS`/`NPTS`/`SWAP`/`KQUEUES`/`UMTXP` return infinity (FreeBSD proc-0); `RLIMIT_DATA` mirrors host (PS5 12.70 payload: 0x800000000). `RLIMIT_NOFILE` returns `EMFILE` limit (soft/hard): Windows 8192 CRT fds/stdio (from 512 via [`_setmaxstdio`](https://learn.microsoft.com/en-us/cpp/c-runtime-library/reference/setmaxstdio)); Linux host hard (soft raised at load); macOS `min(hard, kern.maxfilesperproc)`. ## change [read, write and vector I/O]

- [read, write and vector I/O](../../../core/libs/prx/libkernel/File/src/Stdio.cpp) (libkernel) on guest sockets use flagless `recv`/`send`; `sceKernelReadv`/`sceKernelWritev` gather/scatter in one socket call, keeping stream short reads and datagram boundaries. `pread`/`pwrite`/`preadv`/`pwritev` (and `sceKernel` forms) return `ESPIPE` on open sockets and `EBADF` on closed ones. On Linux, write `EPIPE` raises host `SIGPIPE` (guest signal 13) unless `SO_NOSIGPIPE` is set: ignoring gives `EPIPE`, a handler runs (or stays pending if 13 is blocked under a handler), while blocking 13 under default disposition does not prevent host termination (like other host-mapped signals); Windows raises nothing. `write` > `INT_MAX` returns `EMSGSIZE` where the console sends it; socket AIO still goes to the host, which lacks the descriptor.

## change [Socket descriptor numbers]

- [Socket descriptor numbers](../../../core/libs/prx/libkernel/Socket/src/Udp.cpp) (libkernel, libSceNet) - `socket`, `accept`, `socketpair`, `dup`, `sceNetSocket`, `sceNetAccept` take the lowest free host file descriptor (matching FreeBSD 11.4 `fdalloc` in `kern_descrip.c`), keeping numbers < `FD_SETSIZE` (1024) while <1024 descriptors are open. The slot holds a zero-access `NUL` handle on Windows and a dup'd host socket on Linux, mapped by socket tables. Host runtime files shift numbers vs console; initial console `socket`/`sceNetSocket` numbers and `getdtablesize` are unmeasured. Table-bypassing paths see the placeholder: libc `fdopen` opens it, and `sceKernelClose` on a libSceNet socket frees the fd but leaves the libSceNet socket open. Palworld (PPSA23126), The Mound (PPSA26223) and Dying Light 2 (PPSA02262) set socket bits in 1024-bit `fd_set`.

## change [kevent on a pipe]

- [kevent on a pipe](../../../core/libs/prx/libkernel/Equeue/src/Kqueue.cpp) (libkernel) - host pipes are one-way unlike FreeBSD [`kern_pipe`](https://github.com/freebsd/freebsd-src/blob/release/11.0.0/sys/kern/sys_pipe.c#L422): `EVFILT_READ` on write ends and `EVFILT_WRITE` on read ends throw. macOS `EVFILT_WRITE` reads anonymous-pipe free space via 0-timeout private kqueue; named FIFOs (`F_GETPATH`) throw (writable post-close without `EV_EOF`). `EVFILT_WRITE` uses host buffer space (not 16 KiB) and fires on Linux when writable rather than `PIPE_BUF` (512) free. Windows pipes poll every 1 ms and `fcntl` cannot make write ends non-blocking. Else [`filt_piperead`](https://github.com/freebsd/freebsd-src/blob/release/11.0.0/sys/kern/sys_pipe.c#L1787-L1828)/`filt_pipewrite`: `EV_EOF` on close, `EPIPE` adding write post-reader-close, `NOTE_LOWAT` ignored.

## change [pause, sigsuspend, sigwait, sigwaitinfo]

- [pause, sigsuspend, sigwait, sigwaitinfo](../../../core/libs/prx/libkernel/System/src/Signals.cpp) (libkernel) use `sigtimedwait` pending set (no cancel). `pause` runs unblocked handler (-1/`EINTR`), drops ignored, `SA_SIGINFO` throws; hostless defaults (not 2,4,6,8,11,15, non-Win 13) stay pending vs FreeBSD kill; unblocked `SIGALRM` exits 142. `sigsuspend` swaps 4-word `_sigprocmask` (null throws). Imports: PPSA68091 (0x8F7266), PPSA99169 (0x30DB1), PPSA99420 (0x3BD80F6/0x3C9E220/0x3C9E4C7/0x3C9E588), PPSA97358 ([compatfd](https://github.com/ZiZc3/XPSemu/blob/8eec07b4e31f66dce8e0b05c1ca1281af303e933/util/compatfd.c#L28-L53)/[main-loop](https://github.com/ZiZc3/XPSemu/blob/8eec07b4e31f66dce8e0b05c1ca1281af303e933/util/main-loop.c#L110-L147)/[dummy](https://github.com/ZiZc3/XPSemu/blob/8eec07b4e31f66dce8e0b05c1ca1281af303e933/accel/dummy-cpus.c#L48-L56) `SIGIO`/`SIGALRM`/`SIGBUS`), PPSA99869 (#5501, post `sysctlnametomib`/`fegetenv`/`mincore`).

## change [sigaction]

- [sigaction](../../../core/libs/prx/libkernel/System/src/Signals.cpp) (libkernel) records 1-128 (`EINVAL` else/`SIGKILL`/`SIGSTOP`, `kern_sigaction`); `signal` sets `SA_RESTART`, empty mask. Non-`SA_SIGINFO` `SIGINT`/`SIGILL`/`SIGABRT`/`SIGFPE`/`SIGSEGV`/`SIGTERM`/non-Win `SIGPIPE` run (no `SA_SIGINFO` `siginfo_t`/`ucontext_t`, no `SIGBUS`/`SIGHUP`, no `SA_ONSTACK`). Running resets `SA_RESETHAND` (`postsig_done`), holds self (sans `SA_NODEFER`)+mask (sans `SIGKILL`/`SIGSTOP`) off `sigprocmask` (reported); `SIG_UNBLOCK`/`SIG_SETMASK` drop holds (restoring pre-handler bit on return, unlike `sigreturn` for handler-added blocks/`sigsuspend`); `longjmp`/`siglongjmp` restores mask. In-handler raises run on `raise` return (async waits for next `raise`/`_sigprocmask`). `raise`/`kill` take 1-128 (blocked->`sigtimedwait`, handler->caller, unblocked hostless w/o handler->`EINVAL`; `raise` `SA_SIGINFO` throws).

## change [Regular file mappings]

- [Regular file mappings](../../../core/libs/prx/libkernel/DirectMemory/PosixMemory.cpp) (libkernel) - Linux `mmap` maps regular files like shm (Dusklight PPSA99305 SQLite `-shm`; FreeBSD 11 `mmap(2)`/shadPS4 `MemoryManager::MapFile`; console unmeasured; pipes/sockets/dirs/devs->`EOPNOTSUPP`). Windows shared maps use `CreateFileMappingW` (`shm_open`/JIT temp files too), `ReOpenFile` for `PROT_EXEC` (`EACCES` on ACL), separate sections per `mmap` (no alias tracking); `GuestArenaMapAlias` fails RO (`PAGE_READWRITE`) and throws on EOF pages; `mprotect` past view (`EACCES`) and shrinking `ftruncate` while mapped (`EINVAL`) fail; shared maps may end in EOF 16 KiB page per POSIX [`mmap`](https://pubs.opengroup.org/onlinepubs/9799919799/functions/mmap.html) (PS5LM Plus PPSA99581 llama.cpp; 4 KiB EOF + private zero tail, ignores growth). Past-EOF, WO fds, Windows private-map (copied at `mmap`) -> `EOPNOTSUPP` (vs `SIGBUS`/`vn_mmap`/Linux `EACCES`).

## change [sendfile]

- [sendfile](../../../core/libs/prx/libkernel/Socket/src/Udp.cpp) (libkernel) follows FreeBSD 11 `sendfile` on connected stream sockets: sends headers, file from `offset` (`nbytes` 0 = to EOF) in 64 KiB `sceKernelPread`/`send` blocks, and trailers, leaving file offset unchanged and returning `EAGAIN` with `*sbytes` on partial non-blocking sends. Non-regular/non-shm fds (sockets, `/dev/urandom`, kqueue) fail with `EINVAL` and `*sbytes` 0 per [`sendfile_getobj`](https://github.com/freebsd/freebsd-src/blob/8c639945a44588f6cfdddfb057bb5aad88735da0/sys/kern/kern_sendfile.c#L421-L463); bad `headers`/iovecs fail `EFAULT` (`copyin`/`copyinuio`), unwritable `sbytes` is ignored like FreeBSD [`copyout`](https://github.com/freebsd/freebsd-src/blob/release/11.4.0/sys/kern/kern_sendfile.c#L982-L983). `flags` are ignored (`SF_NODISKIO` never returns `EBUSY`; `SF_SYNC` returns when queued). Imported by PS5MC (PPSA99420).

## change [getpriority]

- [getpriority](../../../core/libs/prx/libkernel/System/src/Process.cpp) (libkernel) follows FreeBSD 11.4 [`sys_getpriority`](https://github.com/freebsd/freebsd-src/blob/8c639945a44588f6cfdddfb057bb5aad88735da0/sys/kern/kern_resource.c#L93-L165): `PRIO_PROCESS`/`PRIO_PGRP` with 0 or own pid and `PRIO_USER` with 0 return 0 (preserving errno); other ids return `ESRCH` and other `which` `EINVAL`. `setpriority` uses the same lookup, denies negative nice with `EACCES` (`donice`/`PRIV_SCHED_SETPRIORITY`/`prison_priv_check` assuming jailed title, unmeasured; payload accepted -25/-5), ignores `PRIO_PROCESS` >=0 (keeping 0, matching PS5 13.60 payload for -25,-5,5,25), and throws on `PRIO_PGRP`/`PRIO_USER` >=0 (unverified). Title reads and host nice (`APS5_THREAD_PRIORITY=high`) are unreported/unverified; `scePthread`/`sceKernel` priority calls do not use `setpriority`.

## change [sceKernelStopUnloadModule]

- [sceKernelStopUnloadModule](../../../core/libs/prx/libkernel/Module/src/Module.cpp) (libkernel) never calls `module_stop` (relinker lifecycle metadata records none) and stores 0 in `res`. ## change [symlink]

- [symlink](../../../core/libs/prx/libkernel_sys/Export.cpp) (libkernel_sys) stores the target verbatim in a host symlink followed by the host rather than the guest resolver. Absolute targets throw (would need host path + `readlink` translation). `..` components are allowed only when host physical and guest lexical resolution match: every traversed directory must exist and not be a symlink, and the host-joined target must match guest mount resolution (`..` escaping `/savedata0` or crossing a symlink throws, unlike FreeBSD 11.4 `namei`). A PS5 11.60 payload rejected a relative target in its data directory with `EOPNOTSUPP`, whereas this creates it; other directories/absolute targets unmeasured.

# relinker

## change `--frame-red-zone` frames only leaf functions

- `--frame-red-zone` frames only leaf functions starting with pushes (`push rbp; mov rbp, rsp; push ...`, or pushes with optional `sub`/`lea` allocation) or neither pushes nor allocation, and exiting by undoing the allocation, popping the same registers, and `ret` ([framer](../../../core/relinker/codegen/src/x86/RedZoneFramer.cpp)). Short prologues/exits (<5-byte jump) absorb adjacent straight-line instructions. Leaves keep their red zone if 5 bytes cannot be formed, a branch targets an absorbed instruction or widened-prologue start, a pushless leaf pushes/pops, a frameless leaf pushes/pops in its body (preventing mis-indexed pops, shrink-wrapped spills over RSP, or shifted RSP operands), a frame-pointer leaf allocates, an exit frees a different size, or indirect jumps/other RSP arithmetic occur.
