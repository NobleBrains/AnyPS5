## change [sem_timedwait](../../../core/libs/prx/libkernel/Pthread/Posix/Sem.cpp)

- [sem_timedwait](../../../core/libs/prx/libkernel/Pthread/Posix/Sem.cpp) (libkernel) consumes an available count before checking the timeout and waits indefinitely on a null timeout, per FreeBSD 11 `sem_timedwait`. PS5 payload measurements (FW 13.60) matched: with an available count, null timeout, `tv_nsec` of -1 or 1000000000, and past deadlines all returned 0 and took the count; with none, invalid `tv_nsec` failed with `EINVAL`, and past deadlines or negative `tv_sec` with `ETIMEDOUT`. PPSA29866 (call site `0x130916`) calls it from a wait helper that reads clock id 0 into a zeroed 16-byte struct, adds `ms * 1,000,000` normalized below `1e9` (never null), retries on error 4, and returns false on any other error or clock failure, giving no evidence on null or invalid timeouts.

## change [sem_setname](../../../core/libs/prx/libkernel/Pthread/Posix/Sem.cpp)

- [sem_setname](../../../core/libs/prx/libkernel/Pthread/Posix/Sem.cpp) (libkernel) takes `(sem, const char* name)` and models only the one-time registration flag on the host semaphore via `namedobj_create` without storing/reading back the name. In `libkernel`, the semaphore's first dword holds `0xffff736d` before the call and `(id << 16) | 0x736d` after; a second call or zeroed semaphore returns -1 with `EAGAIN` and no syscall (per BunnyFl FW 13.42 disassembly and #11267). Destroyed semaphores (zeroed here) behave as zeroed; null `sem` or failing `namedobj_create` throws (console faults on null `sem`; kernel errors unknown). ## change [Windows directory descriptors](../../../core/libs/prx/libkernel/File/src/DirectoryDescriptor.cpp)

- [Windows directory descriptors](../../../core/libs/prx/libkernel/File/src/DirectoryDescriptor.cpp) (libkernel) snapshot on first `getdents`/`getdirentries` or non-zero `lseek` (`SEEK_SET`/`SEEK_CUR`); `lseek(0)` discards it so next read re-lists in O(entries). `lseek` uses entry indices (`SEEK_CUR` 0 returns index; `SEEK_END` throws as FreeBSD directory size is unmodelled); negative results return `EINVAL` and `SEEK_CUR` overflow returns `EOVERFLOW` (FreeBSD `vn_seek`). ## change [sceKernelAddReadEvent and sceKernelAddWriteEvent](../../../core/libs/prx/libkernel/Equeue/Equeue.cpp)

- [sceKernelAddReadEvent and sceKernelAddWriteEvent](../../../core/libs/prx/libkernel/Equeue/Equeue.cpp) (libkernel): read events on listening sockets (here and `kevent`) report completed connections pending `accept` in `data`, matching FreeBSD 11.4 [`filt_solisten`](https://github.com/freebsd/freebsd-src/blob/release/11.4.0/sys/kern/uipc_socket.c#L3384-L3392) (`so_qlen`): Linux TCP uses `TCP_INFO` `tcpi_unacked`, while non-TCP/other OSes report 1 when pending. ## change [sceKernelAddReadEvent and sceKernelAddWriteEvent on regular files](../../../core/libs/prx/libkernel/Equeue/Equeue.cpp)

- [sceKernelAddReadEvent and sceKernelAddWriteEvent on regular files](../../../core/libs/prx/libkernel/Equeue/Equeue.cpp) (libkernel) are the other exception: size > 1, directories, and other vnode types throw, and console `vfs_kqfilter` behavior is unmeasured. ## change On macOS the Rosetta main stack and the stacks of the host threads lie inside the guest arena

- On macOS the Rosetta main stack and the stacks of the host threads lie inside the guest arena, where titles can map fixed addresses. `Aps5StartGuest` moves the main thread to a 16 MiB stack at `0x600000000000`, copies `argv`, `environ`, program name, and initial block, and frees the old stack to the arena except the top 2 pages (8 KiB of the 8372224-byte stack on macOS 27.2, Apple M5 x86-64 under Rosetta) holding the process start block ([MainThreadMacOs.cpp](../../../core/libs/prx/libkernel/Pthread/src/MainThreadMacOs.cpp)). Those pages stay mapped because dyld keeps unredirectable pointers there (`_NSGetExecutablePath`, libxpc, Cocoa, `ShaderCacheDirectory` faulted when freed); block is kept whole only if `argv` still points into the stack. Guest/other host thread stacks remain on system allocations (fixed overlap fails). Move is skipped if main stack is outside arena, new stack cannot be placed outside, or host is non-x86-64.
